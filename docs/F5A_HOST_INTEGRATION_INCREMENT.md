# F5.A host integration increment

This increment exposes the closed F5.A personal-calendar read path through the current interaction-purpose runtime without weakening its specialized authority, acquisition, cognition, or presentation boundaries.

The exact supported calendar question grammar is classified before generic F4 response routing. If the specialized calendar coordinator is absent, the current runtime fails closed rather than treating the request as a generic world question or conversational response.

The coordinator composes the existing hardened F5.A services. Runtime selection of a Permission, CredentialBinding, or model route is only identifier resolution: every personal-calendar page transport, model transport, and payload-bearing presentation remains independently authorized by the specialized service at its own current-state boundary.

Stable stage operation identities allow a completed interaction to recover canonical Investigation, Observation, acquisition, projection, generation, adoption, and accepted presentation state after process restart without replaying provider, model, or personal-data presentation transports. Unresolved model dispatch remains explicitly recovery-required. Uncertain presentation remains subject to exact-generation content-free reconciliation and cannot authorize payload resend.

This increment intentionally does not add a concrete calendar provider connector or extend process configuration with calendar credentials. Those are separate integration contracts. The ordinary runtime therefore exposes the specialized routing seam while remaining fail-closed unless qualified personal-calendar adapters and policy state are explicitly supplied.
