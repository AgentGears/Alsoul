# F5.A host integration increment

This increment exposes the closed F5.A personal-calendar read path through the current interaction-purpose runtime without weakening its specialized authority, acquisition, cognition, or presentation boundaries.

The exact supported calendar question grammar is classified before generic F4 response routing. If the specialized calendar coordinator is absent, the current runtime fails closed rather than treating the request as a generic world question or conversational response.

The coordinator composes the existing hardened F5.A services. Runtime selection of a Permission, CredentialBinding, or model route is only identifier resolution: every personal-calendar page transport, model transport, and payload-bearing presentation remains independently authorized by the specialized service at its own current-state boundary.

Recovery resumes from the furthest trustworthy durable stage. A completed acquisition is reused without requiring current provider credential feasibility; a completed model generation is reused without requiring the historical route to remain active; and an accepted or uncertain presentation is reconciled without requiring current read authority. Current Permission, credential, or route selection occurs only when the corresponding new provider, model, or payload transport is actually required.

A failed acquisition advances to a fresh bounded Investigation/Observation generation. An unresolved in-progress acquisition remains fail-closed under the acquisition service's recovery contract. Stable generation-specific operation identities prevent a failed observation from being silently replayed as a new acquisition while preserving deterministic recovery of completed stages.

Accepted presentation recovery can repair historical Timeline truth after later revocation without redisclosing the payload. Uncertain presentation remains subject to exact-generation content-free reconciliation; only authoritative terminal `NOT_ACCEPTED` can make a new payload generation eligible, and that new payload still requires a fresh current disclosure gate.

This increment intentionally does not add a concrete calendar provider connector or extend process configuration with calendar credentials. Those are separate integration contracts. The ordinary runtime and host application expose the specialized orchestration seam while remaining fail-closed unless qualified personal-calendar adapters and policy state are explicitly supplied.
